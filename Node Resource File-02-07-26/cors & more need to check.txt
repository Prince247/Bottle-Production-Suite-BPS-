how system runs

CORS allows frontend and backend on different domains to communicate.

When frontend runs on port 3000 and backend on 3020, they are different origins, so CORS is triggered.
Browser sends a preflight OPTIONS request to check if the backend allows this origin.
In the backend, we configure CORS to allow http://localhost:3000.
If allowed, the browser proceeds with the actual request.
CORS is enforced by the browser, and controlled by backend headers.


--
if fe & api runs in same ports then
Same origin → no security issue → no CORS needed"

So:
❌ No preflight
❌ No CORS headers required
✅ Direct request works
---
If it "does not work" even on same port
Then issue is NOT CORS. It could be:
Wrong API URL
Server not running
Routing issue (/api not defined)
Proxy not configured

👉 Flow:

Browser sends request with Origin: http://localhost:3000
Backend checks allowed origins

Backend responds:
Access-Control-Allow-Origin: http://localhost:3000
Browser allows request ✅

👉 OFFSET means:skip first N rows, then take LIMIT
LIMIT 50 OFFSET 0 -> OFFSET 0 → skip none → start from 1
LIMIT 50 OFFSET 50 -> OFFSET 50 → skip first 50 → start from 51
3. Indexing - Improves SELECT performance, Slightly slows INSERT/UPDATE
4. Views vs Materialized Views
✅ View:
Just a saved query
Runs every time → slower
“View does not store data, it executes query each time.”
✅ Materialized View: Materialized view stores data physically in the database, unlike normal views.
Stores actual data (like table)
Faster reads
REFRESH MATERIALIZED VIEW view_name;

Node Working
Node.js is single-threaded (main thread)
Uses Event Loop to handle async tasks
Execution:
Sync code → runs first
Microtasks → (Promises)
Macrotasks → (setTimeout, I/O)

👉 Order:

Call stack
Microtask queue (Promises)
Macrotask queue
Thread / Thread Pool:
Heavy work (DB, file, crypto) → handled by thread pool (libuv)
Not blocking main thread
