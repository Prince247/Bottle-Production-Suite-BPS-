✔️ Very short interview version
Node.js is single-threaded for JavaScript execution, but internally it uses libuv, thread pool for certain operations, 
allowing it to handle multiple requests concurrently without blocking the main JavaScript thread.


✔️ How Nodejs Works?
-> Node.js is a JavaScript runtime that uses the V8 engine to execute JavaScript code. 
When a request comes to a Node.js server, If the code is a normal synchronous operation, V8 executes it directly on the Call Stack. once 
it done 2nd priority is Process.nextTick() But if the code performs an asynchronous operation such as reading a file system, doing certain cryptographic work, compression, or some DNS operations, 
Node.js uses libuv to handle that operation without blocking the main JS thread.
libuv uses Thread Pool. The Thread Pool has a default size of 4 threads and can be increased using UV_THREADPOOL_SIZE up to 128. 
While that asynchronous operation is running, Node.js can continue executing other JavaScript code instead of waiting for it. 
Once the asynchronous operation finishes, its callback is made ready to be executed and is placed into the appropriate queue. 
This is where the Event Loop becomes important: the Event Loop continuously checks whether the Call Stack is empty
When the Call Stack is empty, it takes micro & macro task execute through V8. This is how Node.js can handle many concurrent requests even though JavaScript itself runs on a single main thread.

process.nextTick() puts the function into Node's special nextTick queue. 
After the current synchronous execution finishes, Node processes that queue, and the function is then executed by V8 on the Call Stack.

✔️Node.js uses libuv internally to handle blocking operations like file system, crypto, DNS, and compression. 
These tasks are offloaded to a thread pool (default size 4). Once completed, the result is placed in a queue, 
and the event loop pushes it to the call stack where JavaScript executes the callback. Developers don’t use libuv directly — 
Node handles it automatically.can be increased up to 128 using the UV_THREADPOOL_SIZE environment.

✔️ EventEmitter is basically a synchronous event mechanism that runs on the main JavaScript thread
const EventEmitter = require('events');
const emitter = new EventEmitter();
emitter.on('hello', () => {
    console.log('Listener 1');
});
emitter.on('hello', () => {
    console.log('Listener 2');
});
emitter.on('hello', () => {
    console.log('Listener 3');
});
emitter.emit('hello');
console.log('Done');

Execution is:
emit('hello')
      ↓
Listener 1
      ↓
Listener 2
      ↓
Listener 3
      ↓
Done

When emitter.emit('hello') is executed, all listeners registered for the hello event are executed synchronously, 
one after another, on the main JavaScript thread. If any listener performs blocking work, it blocks the main thread, 
so other JavaScript callbacks cannot execute until that work finishes.

✔️ A closure Defination & Code 
Closure is a function that remembers variables from its outer scope even after the outer function has finished execution. 
So, closure helps in maintaining private data and allows controlled access, just like a real bank system.
example - In a bank account, the actual balance is not directly accessible from outside. 
You cannot just go and modify the balance manually. Instead, the bank provides methods like 
deposit and withdraw to interact with it.

function createAccount() {
let balance = 0; // private variable

function deposit(amount) {
balance = balance + amount;
console.log("After deposit:", balance);
}

function withdraw(amount) {
balance = balance - amount;
console.log("After withdraw:", balance);
}

// returning functions
return {
deposit: deposit,
withdraw: withdraw
};
}

// create account
const account = createAccount();

// use it
account.deposit(100);   // After deposit: 100
account.withdraw(30);   // After withdraw: 70
